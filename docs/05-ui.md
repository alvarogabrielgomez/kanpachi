# UI

## Principio

Dos estados, cero configuración. La UI muestra el estado del sistema en lenguaje humano y nunca pide decisiones técnicas. Todo lo que el daemon sabe (directo o relay, qué puertos están abiertos, por qué falló algo) se dice en texto plano.

## Pantalla 0: tu nombre

Aparece una sola vez, la primera vez que se abre la app. Implementa la decisión 21.

```
┌──────────────────────────────────────────────┐
│                                              │
│   ¿Cómo te ven tus panas?                    │
│                                              │
│   ┌────────────────────────────┐             │
│   │ Alvaro                     │             │
│   └────────────────────────────┘             │
│   Hasta 12 letras y números                  │
│                                              │
│   Es solo para que se reconozcan en la       │
│   lista. No es una cuenta, no se verifica,   │
│   no se manda a ningún servidor.             │
│                                              │
│              ┌───────────────┐               │
│              │   Continuar   │               │
│              └───────────────┘               │
└──────────────────────────────────────────────┘
```

- **Obligatorio.** Sin nombre no se entra ni se crea una sala. Es lo único que la app pide en toda su vida.
- Se puede cambiar después desde "Avanzado". El cambio aplica en la próxima sala, no en la activa.
- Validación en vivo: se aceptan letras y números, hasta 12. Lo demás no se puede ni escribir, así no hay mensaje de error que leer.
- El texto de abajo es obligatorio y literal. Es la única pantalla del producto que parece un registro, y desactivar esa lectura vale más que ahorrar tres líneas.
- **Sustituye el nombre del equipo.** Sin esto, el motor publicaría a todos los peers el nombre de la máquina en Windows, que suele traer el nombre real de la persona.

```
│                                              │
│   Código de sala                             │
│   ┌────────────────────────────┐  ┌────────┐ │
│   │ A7K2-M9QX                  │  │ Unirse │ │
│   └────────────────────────────┘  └────────┘ │
│                                              │
│                    o                         │
│                                              │
│   ┌──────────────────────────────┐           │
│   │         Crear sala           │           │
│   └──────────────────────────────┘           │
│                                              │
│   Tus juegos                                 │
│   ┌──────────────────────────────┐           │
│   │  Project Zomboid             │           │
│   │  Minecraft (Java)            │           │
│   │  Terraria                    │           │
│   ├──────────────────────────────┤           │
│   │  Ver toda la biblioteca (18) │           │
│   └──────────────────────────────┘           │
│                                              │
│  ● Servicio activo                           │
└──────────────────────────────────────────────┘
```

- El campo acepta cualquier formato de invite ID y lo normaliza solo: con o sin guiones, mayúsculas o minúsculas, con host embebido (`A7K2M9QX@seed.midominio.com`) o en forma URL (`kanpachi.accentio.dev/A7K2M9QX`, con o sin `https://`). Al pegar, la UI lo reformatea a la forma canónica y muestra el host debajo si no es el por defecto. Un fragmento con la clave de la tarjeta se descarta al pegar: a la app no le sirve, el nombre de la sala lo recibe por el canal de control.
- **"Crear sala" no pide juego.** Pide un nombre para la sala, y nada más. La sala es independiente del juego activo, decisión 20: nace con red cifrada y cero puertos abiertos, que es un estado válido, y el juego se elige adentro. El nombre es presentación pura, viaja cifrado dentro de la tarjeta y el seed no puede leerlo; se acota a 40 caracteres al escribirlo, no solo al mostrarlo, para que el host vea lo mismo que van a ver los demás.
- **La detección ordena, jamás filtra.** Arriba aparecen los juegos detectados como instalados, que es el atajo del 90% de los casos. Debajo, siempre visible, el acceso a la biblioteca completa del catálogo, con buscador. La detección puede fallar por muchas razones (juego fuera de Steam, instalado en una unidad rara, comprado en Epic o GOG, manifiesto que no se pudo leer) y ninguna de ellas puede impedir crear una sala.
- Si el usuario elige un juego que la detección no encontró, se crea la sala igual, sin advertencias ni fricción. Kanpachi no tiene por qué tener la razón sobre qué hay instalado en la máquina.
- El punto de estado inferior refleja el servicio: verde activo, gris arrancando, rojo con mensaje accionable.

### Por qué volviste a esta pantalla

Si la sesión anterior terminó sola, la pantalla lo dice en una línea, arriba del campo de código. Sin esto, que te expulsen, que el host cierre, que desaparezca veinte minutos y salir por tu cuenta se ven exactamente igual.

| Motivo | Texto |
|---|---|
| Saliste tú | Sin texto. No hay nada que explicar |
| El host te sacó | "El host te sacó de la sala." |
| El host cerró la sala | "El host cerró la sala." |
| El host desapareció veinte minutos | "El host llevaba veinte minutos sin aparecer, así que Kanpachi cerró todo lo que había abierto." |
| El túnel no volvió | "La conexión con la sala no volvió. Kanpachi lo intentó durante diez minutos y cerró todo lo que había abierto. Vuelve a pegar el código cuando tengas red." |
| No se llegó a entrar | "No se pudo entrar a la sala." |

Las dos del medio y las dos de abajo llevan la misma coletilla sobre lo que se cerró, y es a propósito: responde la pregunta que la gente se hace sola, que es si quedó algo abierto.

### Volver a la última sala

Debajo del campo de código, si hubo una sala anterior como invitado:

```
│   Volver a la última sala                    │
│   ┌──────────────────────────────┐           │
│   │  Los panas · A7K2-M9QX       │           │
│   └──────────────────────────────┘           │
```

- Es el mismo ingreso de siempre con el código guardado. No hay un camino de entrada distinto, y por lo tanto no hay una forma distinta de fallar.
- **El código guardado se mantiene vigente cuando el host lo renueva**, porque se lo reparte a los que están dentro en ese mismo acto. Ver decisión 23. Sin eso, esta función caducaría en silencio y el usuario lo descubriría al fallar.
- Lo guardado es el código, el seed, el nombre de la sala y tu nick. **Nunca la credencial**: volver pasa otra vez por la puerta del host, que es lo que hace que revocar siga sirviendo.
- Que te hayan expulsado no borra esta entrada. Expulsar no es banear.

### La sala que quedó abierta, solo en el host

Si el daemon murió sin cerrar la sala, al arrancar lo dice y **pregunta**. Nunca la reabre solo:

```
┌──────────────────────────────────────────────┐
│  Tenías una sala abierta                     │
│                                              │
│  "Los panas", con el código A7K2-M9QX.       │
│  Se cerró sin avisar, seguramente por un     │
│  apagón o un reinicio.                       │
│                                              │
│  Si la reabres, vuelve con el mismo código   │
│  y el mismo juego. Quien siga esperando      │
│  reconecta solo.                             │
│                                              │
│      [Cerrarla]      [Reabrir la sala]       │
└──────────────────────────────────────────────┘
```

- Mientras la pregunta está en pantalla, la máquina ya está en cuarentena: el arranque purga las reglas antes de preguntar nada.
- Si la máquina cambió de red y el rango de la sala ahora pisa la LAN de donde está, se dice y no se reabre: "Esa sala usaba un rango que ahora choca con tu red actual. Ciérrala y crea una nueva."

```
│  Tu router sigue cerrado. Internet no ve nada│

│  Solo te conectas con el host. Los demás     │
│  jugadores no alcanzan tu PC.                │
│                                              │
│  En la sala                                  │
│  ● Humberto (host) 100.87.3.1  directo  28ms │
│  ● Gabriel       100.87.3.2   directo   45ms │
│  ◐ Santiago      100.87.3.3   relay    140ms │
│  ● Alvaro (tú)   100.87.3.4                  │

```

- Verde: conexión directa. Ámbar: vía relay, con tooltip "Funciona con más latencia, el NAT de una de las puntas no permitió conexión directa".
- **La topología se dice en texto, siempre.** Sale del perfil del juego, de si `client_ports` está vacío. Con `client_ports` vacío: "Solo te conectas con el host. Los demás jugadores no alcanzan tu PC". Con `client_ports` no vacío: "Este juego conecta a todos con todos. Se abren los puertos del juego hacia los demás miembros". Es la aplicación directa del principio de que la seguridad que no se ve no genera confianza, y es la diferencia que el jugador tiene derecho a conocer antes de entrar.

### Expulsar, solo en la vista del host

Cada miembro de la lista lleva un botón de expulsar, visible **únicamente si tú eres el host**. Implementa la decisión 22.

```
│  ◐ Santiago      100.87.3.3   relay    140ms  [Expulsar] │
```

Al pulsarlo, confirmación de una línea que dice la verdad completa y no promete de más:

```
┌──────────────────────────────────────────────┐
│  Expulsar a Santiago                         │
│                                              │
│  Sale de la sala ahora mismo.                │
│                                              │
│  Puede volver a entrar si todavía tiene el   │
│  código. Para que no vuelva, renueva el      │
│  código: los que ya están dentro se quedan.  │
│                                              │
│   [Cancelar]  [Expulsar]  [Expulsar y        │
│                            renovar el código]│
└──────────────────────────────────────────────┘
```

- **El tercer botón existe porque renovar es el único control que cierra la puerta.** Sin él, el usuario que de verdad no quiere que alguien vuelva tiene que ir a buscarlo a otra parte de la pantalla sin que nada le diga que le hace falta.
- El invitado no ve el botón, ni en su fila ni en las ajenas.
- **Al expulsado sí se le avisa**, y el aviso sale ANTES de cortarle nada, que es el único orden en que puede llegar. Su app dice "el host te sacó de la sala" y cierra limpio. Es cortesía, no es lo que expulsa: un cliente modificado que lo ignore sale igual y en el mismo segundo. Ver decisión 22.
- Los nombres no son únicos. Si hay dos "Santiago", la fila muestra también la IP virtual, que sí lo es.

#### Cuando la expulsión se aplica a medias

Las dos capas corren siempre y ninguna aborta a la otra, así que puede fallar una y funcionar la otra. Eso se dice, no se esconde, y el texto cambia según cuál falló:

| Qué falló | Texto |
|---|---|
| El motor no le cerró la sesión | "Saqué a Santiago de tus reglas: ya no alcanza ningún puerto tuyo. El motor no le cerró la sesión, así que sigue viendo la red. Renueva el código para que no vuelva." |
| Las reglas no se recalcularon | "El motor le cerró la sesión a Santiago. Tus reglas no se recalcularon: vuelve a intentarlo, o vuelve a elegir el juego." |
| Las dos | "No se pudo expulsar a Santiago. Revisa el diagnóstico y renueva el código." |

El aviso se queda en pantalla hasta que las reglas se apliquen bien. Es una de las dos alertas que sobreviven al refresco del módulo de exposición, porque describe algo que pasó y que nadie va a volver a medir.

### Renovar el código

Botón junto al código, visible solo para el host. Es el control que cierra la puerta, separado del que saca a alguien:

```
┌──────────────────────────────────────────────┐
│  Renovar el código de la sala                │
│                                              │
│  El código actual deja de funcionar.         │
│  Los 3 que están dentro siguen dentro.       │
│  Pásales el nuevo solo a quien quieras que   │
│  pueda volver a entrar.                      │
│                                              │
│      [Cancelar]      [Renovar]               │
└──────────────────────────────────────────────┘
```

Las dos perillas son independientes y la UI lo dice con esas palabras, porque la diferencia no es obvia: **expulsar** saca a alguien que está dentro, **renovar** impide entrar a quien está fuera. Ninguna hace el trabajo de la otra.

### Cuando el host se va

Implementa la decisión 20. La conexión sigue bien, lo que falta es la persona que corre el juego, así que no se muestra como error de red:

```
┌──────────────────────────────────────────────┐
│  ⏸  Humberto salió de la sala.               │
│     El juego corría en su PC, así que no hay │
│     a qué conectarse hasta que vuelva.       │
│                                              │
│     Nadie tiene puertos abiertos ahora.      │
│                                              │
│     [Salir de la sala]                       │
└──────────────────────────────────────────────┘
```

- La segunda línea es obligatoria. Es la que responde la pregunta que la gente se hace sola, que es si quedaron expuestos.
- Si el host vuelve, el aviso desaparece solo y la guía de conexión reaparece. No hay que hacer nada.
- **A los veinte minutos, si no volvió, Kanpachi sale solo.** Se cierran los puertos, se revierten los ajustes y se vuelve a la pantalla A diciendo por qué. Cada máquina lo decide por su cuenta, sin coordinarse con nadie: ver decisión 20.
- Nadie hereda el rol. La UI no ofrece "hospedar tú", porque eso es crear una sala nueva.
- El bloque de exposición es obligatorio y literal, y siempre lleva las dos líneas. La primera dice qué se abrió y para quién, la segunda aclara que nada de eso toca el router. Esa segunda línea es el argumento central del producto puesto donde la gente lo lee. Sin juego activo dice: "Nada abierto. La red está en cuarentena. Tu router sigue cerrado".
- Nunca decir "puerto abierto" a secas. Son dos cosas distintas y confundirlas es exactamente el miedo que originó el producto: **puerto en el router** lo alcanza todo internet y Kanpachi jamás lo toca, **puerto en la interfaz virtual** solo lo alcanzan los miembros de la sala.

### Aviso de exposición ajena

Aparece bajo el bloque de exposición cuando la auditoría encuentra reglas del propio juego que lo dejan alcanzable por fuera de Kanpachi:

```
┌──────────────────────────────────────────────┐
│ ⚠  Project Zomboid tiene una regla suya que  │
│    lo deja visible en tu red de casa y para  │
│    toda la sala, fuera del control de        │
│    Kanpachi. Expulsar a alguien no lo tapa.  │
│                                              │
│    [Desactivar mientras juego]  [Dejar así]  │
└──────────────────────────────────────────────┘
```

Al elegir desactivar, la línea pasa a "Regla desactivada. Se restaura al salir de la sala". Nunca se actúa sin ese click. Las reglas se desactivan, jamás se borran.

El texto nombra las dos consecuencias, que es lo que la decisión 12 corrigió: una regla permisiva "en cualquier interfaz" aplica también a `kanpachi0`, así que además de la red de casa abre ese ejecutable a todos los miembros de la sala, incluidos los expulsados. La tercera línea existe para que nadie crea que el botón de expulsar lo resuelve.

- La guía de conexión cambia por perfil: `direct_ip` muestra IP y puerto con botón de copiar, `lan_discovery` muestra "La partida aparece sola en el menú LAN del juego".

### Alertas de exposición

Implementa la decisión 19. Viven en una franja bajo el bloque de exposición, presentes haya sala o no, porque las condiciones que describen existen antes de jugar.

```
┌──────────────────────────────────────────────┐
│ ⚠  Tu Firewall de Windows está apagado.      │
│    Kanpachi se apoya en él para que nadie    │
│    de la sala alcance tu PC. Sin él, no      │
│    puede protegerte.                         │
│    [Cómo activarlo]                          │
├──────────────────────────────────────────────┤
│ ⚠  Tu router tiene abierto el puerto 16261   │
│    hacia internet. Kanpachi no lo necesita:  │
│    hace el túnel sin abrir nada. Mientras    │
│    siga así, cualquiera en internet llega a  │
│    ese puerto.                               │
│    [Cómo cerrarlo]                           │
├──────────────────────────────────────────────┤
│ ⚠  Kanpachi no pudo comprobar si el Firewall │
│    de Windows está encendido ni si sus       │
│    reglas siguen puestas. No quiere decir    │
│    que algo esté mal: quiere decir que nadie │
│    lo está vigilando. Reinicia Kanpachi y si │
│    sigue igual, copia el diagnóstico.        │
│    [Copiar diagnóstico]                      │
└──────────────────────────────────────────────┘
```

**La tercera es distinta de las otras dos y el texto tiene que dejarlo claro.** Las demás dicen que encontraron algo; esta dice que no pudo mirar. Sin ese aviso, una auditoría caída y una máquina impecable se ven idénticas desde acá: las dos pintan verde. Aparece cuando falla cualquiera de los dos chequeos locales, y se va sola cuando vuelven a contestar. La consulta al router no la levanta, porque la mayoría de los routers nunca contestan y el aviso quedaría encendido para siempre.

Reglas:

- **Nunca bloquean.** Se puede crear y unirse a salas con alertas vigentes. Informan, no impiden. Un falso positivo que deje a alguien sin jugar contradice el principio de que la detección ordena y jamás filtra.
- **Kanpachi no arregla nada por su cuenta.** No enciende el firewall del usuario, no cierra puertos del router. Explica y enlaza a cómo hacerlo. Tocar la configuración global de la máquina sin pedirlo es lo que hace el software que este producto no quiere ser.
- Cada alerta sigue la regla de microcopy: qué pasa, qué significa, qué hacer.
- Desaparecen solas cuando la condición deja de existir. No hay que descartarlas a mano.

## Pantalla C: confirmación de apertura externa

Cuando la app se abre desde un enlace `kanpachi://`, sea desde Telegram o desde la página de invitación, **nunca entra sola a la sala**. Abre así:

```
┌──────────────────────────────────────────────┐
│                                              │
│   Te invitaron a una sala de Kanpachi        │
│                                              │
│   Sala       A7K2-M9QX                       │
│   Servidor   kanpachi.accentio.dev           │
│   Host       Humberto  ab3f-9k2m             │
│              ✓ ya jugaste con él, 3 salas    │
│                                              │
│   Al entrar, tu equipo se conecta con los    │
│   demás miembros de esta sala. Nada de tu    │
│   PC queda expuesto hasta que se elija un    │
│   juego.                                     │
│                                              │
│   ┌──────────────┐   ┌───────────────────┐   │
│   │   Cancelar   │   │  Entrar a la sala │   │
│   └──────────────┘   └───────────────────┘   │
└──────────────────────────────────────────────┘
```

**Acá es donde la decisión 25 vale de verdad.** La página web muestra el nick sin poder juzgarlo, porque el navegador no recuerda con quién jugaste. Esta pantalla sí tiene la libreta, así que es la única que puede pronunciarse.

| Lo que dice la libreta | Lo que muestra la tarjeta |
|---|---|
| Nick conocido, misma huella | `✓ ya jugaste con él, 3 salas`, en verde discreto |
| Nick nuevo, huella nueva | `Primera vez que ves a esta persona`, en gris, sin alarma |
| **Nick conocido, huella distinta** | **`⚠ Esta NO es la llave del Humberto que conoces`**, en rojo, y el botón de entrar pasa a segundo plano detrás de "Entrar igual" |
| Sin tarjeta o firma inválida | La línea del host no aparece. No se inventa un nombre |

El aviso rojo no bloquea. Cambiar de máquina o reinstalar Windows produce una huella nueva legítimamente, y bloquear convertiría un caso común en soporte. Lo que hace es invertir el peso visual, o sea que entrar deja de ser el camino cómodo.

Reglas:

- **Siempre aparece.** No hay "recordar esta sala" ni "no volver a preguntar". El estado recordado de confianza se eliminó del diseño precisamente para que no exista forma de saltarse esta pantalla.
- **El diálogo del navegador no la reemplaza.** Chrome y Edge preguntan si abrir Kanpachi, sin decir a qué sala ni a qué servidor, y ofrecen recordar la elección. Esta pantalla es la que muestra los datos concretos.
- **El servidor se muestra siempre**, sea el por defecto o uno ajeno. Si no es el por defecto, la línea va resaltada con la nota "Servidor de otra persona. Solo ve tu IP pública, no puede entrar a la sala ni leer el tráfico".
- **La huella se muestra aunque sea conocida.** Verla siempre es lo que hace que verla cambiar signifique algo.
- Cancelar deja la app en la pantalla A, sin haber tocado nada.
- Un invite ID con formato inválido no llega aquí: se ignora y la app abre en la pantalla A normal.


## Estados del sistema en la UI

| Estado del daemon | La UI muestra |
|---|---|
| Resolving / Connecting | Spinner con "Buscando la sala..." |
| Connected (direct) | Lista de peers, todo normal |
| Connected (relay) | Igual, con los peers en ámbar donde aplique |
| Degraded | Banner ámbar: "Conexión inestable, reintentando" |
| Reconnecting | Banner: "Reconectando..." (tras suspender o cambiar de red) |
| Idle | Pantalla A, con el motivo de la salida si hubo uno |

**`Reconnecting` está acotado a diez minutos.** Pasado ese plazo se sale de la sala, se cierran los puertos y se revierten los ajustes, con el texto de "la conexión con la sala no volvió". La ruedita nunca es eterna, y eso vale escribirlo: una ruedita sin final es la forma más común de que una app mienta.

## Bandeja del sistema

Cerrar la ventana no cierra la sala: el daemon la sostiene. Queda un icono en la bandeja con tres elementos: estado (color), "Abrir Kanpachi", "Salir de la sala". Nada de menús profundos.

## Errores como frases accionables

| Situación | Texto |
|---|---|
| Código con formato inválido | "Ese código no parece completo. Son 8 caracteres, revisa que se copió entero." |
| Sin respuesta de semillas | "No hay conexión con el servidor de encuentro. Revisa tu internet, si persiste avisa en el grupo." |
| UDP bloqueado (según Diagnostics) | "Tu red bloquea el tráfico del juego (UDP). En redes de oficina o universidad suele pasar. Vas a ir por relay, con más latencia." |
| Versión incompatible | "Tu versión de Kanpachi es vieja para esta sala. Pide el instalador nuevo en el grupo." |
| Sala sola por mucho rato | "Llevas 10 minutos solo en la sala. ¿El código llegó bien al grupo?" |
| MTU sospechoso tras el sondeo | "Tu conexión maneja paquetes más chicos de lo normal. Ajusté la red para eso. Si el juego conecta y se queda cargando, avisa." |
| Conflicto de rango detectado | "Tu red de casa usa el mismo rango que Kanpachi. Cambié el nuestro para no romperte internet." |
| Ajustes revertidos por Windows | Sin texto. Se reaplican solos y en silencio. Al usuario no le interesa saber que Windows le borró una métrica |
| El túnel no volvió en diez minutos | "La conexión con la sala no volvió. Kanpachi lo intentó durante diez minutos y cerró todo lo que había abierto. Vuelve a pegar el código cuando tengas red." |
| Reglas propias alteradas y repuestas | Sin texto. Se reponen solas, igual que los ajustes del adaptador |
| Reglas propias alteradas tres veces seguidas | "Algo está borrando las reglas de Kanpachi. Suele ser un antivirus. Mientras pase, la sala puede no funcionar." |

Regla de microcopy: cada error dice qué pasó, qué significa para el usuario y qué hacer, en ese orden, en español coloquial. Jamás un código de error a secas.

## La página de invitación

Vive fuera de la app y forma parte de la experiencia, así que se documenta aquí. Patrón conocido: es lo que hace Discord con sus invitaciones.

```
kanpachi.accentio.dev/A7K2M9QX            funciona pelado
kanpachi.accentio.dev/A7K2M9QX#clave      además muestra el nombre de la sala
```

La sirve el registro del seed, renderizada en el servidor, ver decisiones 17 y 24. El fragmento lleva la clave de la tarjeta y es opcional.

```
│  Internet no ve tu PC.                       │
│  ──────────────────────────────────────      │

```

**"Se identifica como", no "te invitó".** El nickname no se verifica, decisión 21, así que la página no puede afirmar quién es.

**La huella de la llave del host NO va acá.** Se evaluó ponerla al lado del nick y se descartó: el navegador no tiene memoria de con quién jugaste, o sea que la huella aparecería sin nada contra qué compararla. Ocho caracteres que nadie puede juzgar no informan, decoran, y peor, aparentan una verificación que en esta pantalla no ocurre. La comparación vive donde está la libreta, que es la tarjeta de confirmación de la app. Ver decisión 25.

Sin fragmento, o con una clave que no descifra, caen el nick y el nombre de la sala. El avatar vuelve a la marca de Kanpachi en vez de la inicial, y el encabezado dice "Te invitaron a una sala de Kanpachi". Quedan el contador, el ID y el botón. Es el caso de un ID dictado por teléfono, y tiene que verse deliberado y no roto.

**El aviso de seed ajeno va en el pie, no en los chips.** Se probó como un tercer chip y falló por dos motivos: empujaba la fila a dos líneas rompiendo la composición, y le repetía el dominio a alguien que ya lo tiene en la barra de direcciones. Cuando el seed no es el de Accentio, el host del pie va en ámbar y nada más. Es un dato, no una alarma.

La advertencia con peso es la de la pantalla C, que muestra el servidor siempre, lo resalta si es ajeno, y no se puede saltar. Poner una alarma en una página web que cualquiera puede servir tiene poco valor: quien monta una invitación falsa también controla lo que esa página dice de sí misma.

### Portada, en `/`

Llegar sin código no es un error del usuario, así que no se ve como uno. Es la portada del producto y tiene exactamente dos salidas.

```
┌──────────────────────────────────────────────────┐
│                   kanpachi                       │
│   Jugar en LAN con tus panas, sin abrir puertos  │
│              ni crear cuentas.                   │
│                                                  │
│   ¿TE PASARON UN CÓDIGO?                         │
│   ┌────────────────────────────┐  ┌──────────┐   │
│   │ A7K2-M9QX                  │  │  Entrar  │   │
│   └────────────────────────────┘  └──────────┘   │
│   El código no es una contraseña: te lleva a la  │
│   puerta, no te mete adentro. Quien te deja      │
│   entrar es el host, y puede revocarte.          │
│                                                  │
│   ──────────── O EMPIEZA AQUÍ ────────────       │
│                                                  │
│   ┌──────────────────────────────────────────┐   │
│   │     Descargar Kanpachi para Windows      │   │
│   └──────────────────────────────────────────┘   │
│        Windows 10 y 11 · 18 MB · un solo UAC     │
│   ────────────────────────────────────────────   │
│   • Tu router no se toca. …                      │
│   • Solo los puertos del juego. …                │
│   • Sin cuentas ni telemetría. …                 │
└──────────────────────────────────────────────────┘
```

**La descarga se adapta a la plataforma detectada, y la detección jamás bloquea.** En Windows, el botón y su línea de abajo con versión, peso y el único UAC. Fuera de Windows, el botón dice "Descargar el instalador de Windows" y la nota explica que se puede bajar acá para pasarlo al PC, o pedir el código y abrirlo allá. El enlace funciona en las dos, porque la detección por user agent se equivoca y equivocarse no puede dejar a nadie sin salida.

Mientras no haya instalador publicado, el botón lo dice en vez de prometer un archivo que no existe.

**Una frase que NO puede aparecer acá.** El diseño original decía *"el código nunca sale de tu navegador: viaja en el fragmento del enlace y este servidor jamás lo recibe"*. Eso fue cierto y dejó de serlo con la decisión 17: el invite ID va en la ruta y el servidor lo recibe. Mantener esa frase sería mentir justo en la línea que existe para dar confianza. La reemplaza lo que sí es cierto, que el código es un ticket y la cerradura la tiene el host.

**"Entrar" es un enlace con `href`, no una navegación por JavaScript.** Dos motivos: deja el único `window.location.href` de la página para el intent `kanpachi://`, que es lo que el test de arquitectura vigila, y de paso funciona con el botón central del ratón y con "abrir en pestaña nueva". Se habilita solo cuando lo escrito tiene forma de invite ID, y con Enter en el campo hace lo mismo. Un código con forma inválida marca el campo y explica el formato; un campo vacío no se regaña.

Los tres puntos de abajo no son marketing, son las tres promesas que el resto del producto tiene que sostener: el router no se toca, solo se abren los puertos del juego activo, y no hay cuentas ni telemetría.

### Móvil o Mac

Se detecta por user agent, o sea que se equivoca. Por eso queda siempre un enlace discreto "ábrelo igual", para que una detección errada nunca deje a nadie encerrado.

### Descarga

En `/descargar`. Versión, tamaño, y el SHA256 del instalador en monoespaciada, que es lo que permite verificar lo que bajaste. Mientras no haya instalador publicado, dice que todavía no lo hay en vez de ofrecer un botón que no lleva a nada.

### Reglas de la página

- **No se dispara el intent al cargar.** Solo con el click. Los navegadores penalizan la navegación a esquemas externos sin gesto del usuario, y una página que abre programas sola es justo lo que un desconfiado espera de un link sospechoso.
- **No se intenta detectar si la app está instalada.** No hay forma confiable, el truco del temporizador falla distinto en cada navegador y versión. El mensaje de "si no pasó nada" cubre el caso sin adivinar.
- **El fragmento es entrada hostil.** Lo controla quien manda el link. Se valida contra el alfabeto, tiene tope de longitud, y se escribe con `textContent` jamás con `innerHTML`.
- **Sin analítica, sin tracking, sin cookies, sin recursos externos.** Coherente con cero telemetría. Los logos van en línea, no como archivos aparte, así una CSP que prohíbe todo lo de fuera sigue valiendo.
- **La página nunca afirma identidad.** Ver decisión 25.
- Las tres salidas conviven sin que la página decida por el usuario: abrir, descargar, o copiar el ID a mano.

## Lo que no existe en la v1

Pantalla de ajustes, asistente de primera ejecución, login, notificaciones push, temas, idiomas adicionales. Si un ajuste se vuelve imprescindible, nace detrás de un enlace "Avanzado" que el 95% jamás abre.

**Tampoco existe, y es a propósito:** ningún aviso, banner o automatismo disparado por abrir un juego. Kanpachi no vigila procesos, así que la UI nunca reacciona a que arrancaste algo. El juego de la sala se elige a mano y esa elección es lo único que abre puertos.
